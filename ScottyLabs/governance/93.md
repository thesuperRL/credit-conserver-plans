# Implementation Plan: Issue #93 - Governance Resets Repository Rulesets

## 1. Problem Analysis

### What Needs to be Solved
The credit-conserver bot, when processing the `ScottyLabs/governance` repository (configured in `config.yml`), performs aggressive git operations including `git reset --hard origin/{default_branch}`. The issue title suggests these operations are interfering with GitHub repository rulesets.

### Root Cause
The system performs two types of git reset operations in `modules/parallel_workflow_runner.py`:
1. **Line 311**: When updating existing PRs with feedback
2. **Line 369**: When creating new triage branches for issues

These `git reset --hard` commands are intended to sync the local clone with the remote default branch, but the issue title suggests this is somehow affecting repository-level rulesets.

### Potential Scenarios
1. **Misconfiguration**: The bot's GitHub token has admin permissions and is inadvertently calling GitHub APIs that modify rulesets
2. **Side Effect**: Git operations are triggering webhook/action workflows that reset rulesets
3. **Title Misleading**: The issue is actually about branch protection bypassing, not ruleset modification
4. **Gitea Specificity**: Since governance is on Codeberg (Gitea), there may be platform-specific behavior

### Why This Matters
- Repository rulesets define critical governance policies (branch protection, required reviews, status checks)
- Resetting these policies compromises repository security and workflow integrity
- The governance repository specifically should maintain strict access controls

## 2. Technical Approach

### Strategy
**Defensive + Investigative Approach**
1. **Audit existing code** to confirm no ruleset-modifying API calls exist
2. **Add safeguards** to prevent accidental ruleset/branch-protection modifications
3. **Add read-only verification** to detect when rulesets change
4. **Log git operations** more verbosely to trace the actual issue
5. **Add explicit skip logic** for sensitive repositories like governance

### Key Decisions
- **Least privilege**: Ensure the bot's token permissions are read/write for content only, not admin
- **Read-only checks**: Add pre/post-operation verification that rulesets haven't changed
- **Repository exemption**: Allow marking repos as "read-only for rulesets" in config
- **Logging**: Enhanced git operation logging to diagnose the actual issue

### Alternative Considered & Rejected
- **Remove git reset entirely**: Would break the PR update workflow
- **Switch to GitHub API for all branch operations**: Over-engineered; git operations are fine, just need safeguards
