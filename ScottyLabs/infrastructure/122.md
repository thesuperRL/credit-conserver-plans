# Implementation Plan: Upgrade to Forgejo 16.0.2 (or later)

## Problem Analysis

### Context
The credit-conserver bot supports multiple Git platforms including Codeberg/Forgejo instances through the `CodebergPlatform` class, which uses the Gitea API v1. The issue indicates that "the service defaults to forgejo-lts" - this suggests either:
1. A self-hosted Forgejo instance is running an old LTS version
2. Documentation references an outdated version
3. The default API URL configuration points to an old instance

### Current State
- `modules/codeberg_platform.py` implements Gitea API v1 client with no version constraints
- Default API URL: `https://codeberg.org/api/v1` (Codeberg's public instance)
- Custom API URLs supported via `platform_urls.codeberg` in `config.yml`
- No explicit version checks or API version negotiation

### Why This Matters
Forgejo 16.0.2+ includes:
- Security patches and bug fixes
- API improvements and new endpoints
- Better performance and stability
- Potential breaking changes that need verification

## Technical Approach

### Strategy
1. **Audit**: Identify where "forgejo-lts" is referenced (deployment configs, docs, default URLs)
2. **Verify API compatibility**: Check if Gitea API v1 behavior changed between old LTS and Forgejo 16.0.2
3. **Update references**: Change all LTS references to 16.0.2+ compatible versions
4. **Add version detection**: Optional - add API version checking for better debugging
5. **Document**: Update deployment docs with version requirements

### Key Decisions
- **Maintain backward compatibility**: Keep Gitea API v1 support (widely compatible)
- **No breaking changes**: Existing Codeberg.org integration continues to work
- **Optional version checking**: Add but don't enforce (allow older self-hosted instances)
- **Document minimum version**: Clear guidance for self-hosted deployments
