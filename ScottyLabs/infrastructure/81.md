# Implementation Plan: Upstream `forgejo_oauth2_app` Resource to `svalabs/forgejo`

## 1. Problem Analysis

**Objective:** Create a Terraform resource `forgejo_oauth2_app` in the `svalabs/forgejo` provider that allows users to manage OAuth2 applications via the Forgejo API.

**Background:**
- The Forgejo SDK (`codeberg.org/mvdkleijn/forgejo-sdk/forgejo`) already provides OAuth2 CRUD operations:
  - `CreateOauth2` - POST `/api/v1/user/applications/oauth2`
  - `GetOauth2` - GET `/api/v1/user/applications/oauth2/{id}`
  - `ListOauth2` - GET `/api/v1/user/applications/oauth2`
  - `UpdateOauth2` - PATCH `/api/v1/user/applications/oauth2/{id}`
  - `DeleteOauth2` - DELETE `/api/v1/user/applications/oauth2/{id}`
- API returns `client_id` and `client_secret` (sensitive, write-only on creation)

**Why this matters:**
- OAuth2 apps are fundamental for third-party integrations with Forgejo instances
- Terraform management enables IaC workflows for CI/CD pipelines, SSO configurations, and API access
- The SDK support exists; only the Terraform resource wrapper is missing

## 2. Technical Approach

**Strategy:**
- Implement a standard Terraform SDK v2 resource following existing patterns in `svalabs/forgejo` provider
- Handle sensitive `client_secret` as write-only (computed, not stored in state after initial creation)
- Use OAuth2 app ID as the Terraform resource identifier
- Support import via `terraform import forgejo_oauth2_app.example <app_id>`

**Key Decisions:**

1. **Schema Design:**
   - Required: `name` (string) - OAuth2 application name
   - Optional: `redirect_uris` (list of strings) - authorized redirect URIs, default `[]`
   - Optional: `confidential_client` (bool) - whether client secret is required, default `false`
   - Computed: `client_id` (string) - OAuth2 client ID
   - Computed, Sensitive: `client_secret` (string) - only available on creation, not refresh

2. **State Management:**
   - `client_secret` is returned only on Create, not on Read (API limitation)
   - Mark `client_secret` as sensitive to prevent logging
   - Document that secret rotation requires resource recreation (`terraform taint`)

3. **API Mapping:**
   - Create: `CreateOauth2()` → store all fields in state
   - Read: `GetOauth2(id)` → update all fields except `client_secret` (not returned)
   - Update: `UpdateOauth2(id)` → patch changed fields (name, redirect_uris, confidential_client)
   - Delete: `DeleteOauth2(id)` → remove from state

4. **Error Handling:**
   - 404 on Read → remove from state (resource deleted outside Terraform)
   - 403/401 → fail with clear auth error message
   - Conflict on Create → fail (name collision)

## 3. Implementation Steps

### Phase 1: Resource Implementation
1. **Create resource file** `resource_oauth2_app.go` in provider's resource directory
   - Define schema with Terraform SDK v2 `schema.Resource`
   - Implement CRUD functions: `resourceOauth2AppCreate`, `resourceOauth2AppRead`, `resourceOauth2AppUpdate`, `resourceOauth2AppDelete`
   - Add `Importer` with `StateContext` function for `terraform import` support

2. **Register resource** in provider's main resource map
   - Add `"forgejo_oauth2_app": resourceOauth2App()` to `Provider()` resources map

3. **Implement Create:**
   - Extract `name`, `redirect_uris`, `confidential_client` from Terraform config
   - Call SDK `CreateOauth2()` with parameters
   - Store returned `client_id` and `client_secret` in state
   - Set resource ID to OAuth2 app ID from response

4. **Implement Read:**
   - Call SDK `GetOauth2(id)`
   - Handle 404 → `d.SetId("")` to remove from state
   - Update state with current `name`, `redirect_uris`, `confidential_client`, `client_id`
   - Do NOT update `client_secret` (not returned by API)

5. **Implement Update:**
   - Detect changes via `d.HasChange()`
   - Call SDK `UpdateOauth2(id)` with modified fields
   - Refresh state by calling Read

6. **Implement Delete:**
   - Call SDK `DeleteOauth2(id)`
   - Handle 404 as success (already deleted)
