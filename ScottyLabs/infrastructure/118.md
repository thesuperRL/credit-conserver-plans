# Implementation Plan: Document Installing to Non-NixOS Hosts

## 1. Problem Analysis

### Current State
- The project currently runs on GitHub Actions (Ubuntu runners) and has basic deployment documentation
- Installation instructions exist but are scattered across README.md, DEPLOYMENT.md, and AGENTS.md
- No dedicated documentation for local installation on various operating systems
- Python 3.11+ requirement mentioned but setup varies by OS
- No guidance for non-GitHub Actions environments (local development, self-hosted runners, other CI systems)

### What Needs to Be Solved
Create comprehensive installation documentation for developers/users who want to run Credit Conserver on:
- **macOS** (Homebrew, system Python, pyenv)
- **Linux distributions** (Ubuntu/Debian, Fedora/RHEL, Arch, Alpine)
- **Windows** (WSL, native Python, PowerShell)
- **Self-hosted CI runners** (Jenkins, GitLab CI, Drone, CircleCI)
- **Containerized environments** (Docker, Podman)

The documentation should be beginner-friendly while addressing platform-specific gotchas.

### Why This Matters
- Lowers barrier to entry for contributors
- Enables local testing without GitHub Actions
- Supports self-hosted deployments
- Improves developer experience across platforms
- Currently unclear how to install `anthropic` package (missing from requirements.txt but imported in code)

## 2. Technical Approach

### Strategy
1. **Single-source documentation**: Create `INSTALLATION.md` as the canonical installation guide
2. **OS-first organization**: Group by operating system, then by installation method
3. **Prerequisite validation**: Include commands to verify successful installation
4. **Troubleshooting section**: Common issues per platform
5. **Reference existing docs**: Link to DEPLOYMENT.md for GitHub Actions setup, AGENTS.md for development workflow

### Key Decisions
- **Add missing dependency**: `anthropic` package is imported but not in `requirements.txt` - will document this fix
- **Python version handling**: Document both system Python and version managers (pyenv, asdf)
- **Virtual environment mandatory**: Emphasize `venv` usage to avoid dependency conflicts
- **Platform parity**: Each OS section follows same structure (Prerequisites → Install → Verify → Troubleshoot)
- **Quick start first**: Begin with fastest path (macOS/Ubuntu) before edge cases
