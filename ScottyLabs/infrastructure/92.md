# Implementation Plan: Remove Deprecated `projects/` Directory from OpenBao

## 1. Problem Analysis

### What Needs to Be Solved
The `projects/` directory in the OpenBao repository has been marked as deprecated and needs to be removed from the codebase. This directory likely contains outdated code, configurations, or project templates that are no longer maintained or used.

### Why This Matters
- **Maintenance burden**: Deprecated code creates confusion for new contributors and maintainers
- **Security risk**: Unmaintained code may contain security vulnerabilities that won't be patched
- **Technical debt**: Keeping deprecated code increases the cognitive load for understanding the codebase
- **Build/test overhead**: Deprecated directories may still be scanned by tools, slowing down CI/CD
- **Documentation drift**: Deprecated code may conflict with current documentation and best practices

## 2. Technical Approach

### Strategy
1. **Discovery phase**: Identify all references to the `projects/` directory across the codebase
2. **Impact analysis**: Determine if any active code depends on files within `projects/`
3. **Safe removal**: Remove the directory and all references
4. **Verification**: Ensure builds, tests, and runtime behavior remain intact

### Key Decisions
- **Complete removal vs. deprecation warning**: Since already marked deprecated, proceed with full removal
- **Git history preservation**: Use `git rm` to maintain history; the directory remains accessible in git history
- **Migration path**: Document any migration steps in CHANGELOG if users reference this directory
- **Backup verification**: Ensure CI passes before merging to catch any hidden dependencies

## 3. Implementation Steps

### Step 1: Audit Current State
```bash
# Check what's in projects/
ls -la projects/
find projects/ -type f | wc -l  # Count files

# Find all references to projects/ directory
git grep -i "projects/" | grep -v ".git"
git grep -i "projects\/" | grep -v ".git"

# Check import statements (language-specific)
git grep -E "from projects\.|import projects" 
git grep -E "require.*projects/|include.*projects/"

# Check documentation references
git grep -i "projects" -- "*.md" "*.txt" "*.rst"
```

### Step 2: Analyze Dependencies
```bash
# Check if any build scripts reference it
grep -r "projects" Makefile makefile build.sh scripts/ 2>/dev/null

# Check CI/CD configurations
grep -r "projects" .github/ .gitlab-ci.yml .circleci/ 2>/dev/null

# Check configuration files
grep -r "projects" *.yml *.yaml *.json *.toml 2>/dev/null
```
