# Implementation Plan: Rewrite Docs in mdbook

## Problem Analysis

### Current State
The documentation is currently split across multiple Markdown files at the repository root:
- **README.md** (7,513 bytes) - System overview, features, architecture, configuration, usage
- **AGENTS.md** (9,419 bytes) - Repository guidelines, architecture, data flow, code conventions
- **DEPLOYMENT.md** (5,367 bytes) - Deployment checklist, setup steps, monitoring, troubleshooting
- **MULTI_PLATFORM.md** (6,277 bytes) - Multi-platform support documentation

### Why This Needs Solving
1. **Discoverability**: Important documentation is buried in separate files without clear navigation
2. **Maintainability**: No single source of truth; documentation updates require editing multiple files
3. **User Experience**: No searchable, web-rendered documentation; users must navigate GitHub file tree
4. **Professional Presentation**: Static markdown files lack the polish of a proper documentation site
5. **Versioning**: No way to version documentation separately from code

### Goals
- Consolidate all documentation into a structured, navigable mdbook
- Maintain existing content while improving organization
- Enable web deployment (GitHub Pages)
- Preserve markdown source for easy editing
- Add search functionality and better navigation

## Technical Approach

### Strategy
Use **mdbook** (Rust-based markdown book generator) to create a static documentation site:

1. **Install mdbook** - Add to CI/CD for automated builds
2. **Structure content** - Organize existing docs into logical chapters
3. **Configure mdbook** - Set up SUMMARY.md for table of contents
4. **GitHub Pages deployment** - Automate build and publish
5. **Redirect old docs** - Keep root docs as stubs pointing to mdbook

### Key Decisions

**Why mdbook over alternatives?**
- **Lightweight**: Single binary, no npm/Python dependencies
- **Fast**: Rust-based, builds in milliseconds
- **Markdown-native**: Uses standard markdown (no custom syntax)
- **Search built-in**: Automatic client-side search
- **GitHub Pages friendly**: Outputs static HTML
- **Widely adopted**: Used by Rust Book, MDN, many OSS projects

**Content Organization**
```

├── src/
│   ├── SUMMARY.md          # Table of contents
│   ├── introduction.md     # Welcome page

│   ├── configuration/      # Setup and config
```

**Deployment Strategy**

- Deploy to `gh-pages` branch
- Access at `https://thesuperRL.github.io/credit-conserver/`

1. **Install mdbook locally**

6. **Migrate AGENTS.md**

   - Move entire file → `docs/src/deployment/checklist.md`
   - Extract "Monitoring" section → `docs/src/deployment/monitoring.md`
   - Extract GitHub Actions details → `docs/src/deployment/github-actions.md`

8. **Migrate MULTI_PLATFORM.md**
   - Move entire file → `docs/src/platforms/multi-platform.md`
   - Extract platform-specific sections into separate files

### Phase 3: GitHub Pages Deployment

9. **Create GitHub Actions workflow** (`.github/workflows/docs.yml`)
   ```yaml
   name: Deploy Documentation
   
   on:
     push:
       branches: [main]
       paths:
         - 'docs/**'
         - '.github/workflows/docs.yml'
     workflow_dispatch:
   
   jobs:
     deploy:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         
         - name: Install mdbook
           run: |
             mkdir -p ~/bin
             curl -L https://github.com/rust-lang/mdBook/releases/download/v0.4.40/mdbook-v0.4.40-x86_64-unknown-linux-gnu.tar.gz | tar xz -C ~/bin
             echo "$HOME/bin" >> $GITHUB_PATH
         
         - name: Build book
           run: mdbook build docs
         
         - name: Deploy to GitHub Pages
           uses: peaceiris/actions-gh-pages@v4
           with:
             github_token: ${{ secrets.GITHUB_TOKEN }}
             publish_dir: ./docs/book
   ```

10. **Enable GitHub Pages**
    - Repository Settings → Pages
    - Source: Deploy from branch
    - Branch: `gh-pages`, folder: `/root`

### Phase 4: Finalize

11. **Update root README.md**
    - Add prominent link to documentation site at top
    - Keep brief introduction (3-5 sentences)
    - Link to full docs: `📚 [Read the full documentation](https://thesuperRL.github.io/credit-conserver/)`

12. **Add stub notices to old docs**
    - Add notice at top of AGENTS.md, DEPLOYMENT.md, MULTI_PLATFORM.md
    - Example: `> ⚠️ This file has been migrated to the [documentation site](https://thesuperRL.github.io/credit-conserver/). Please refer there for the latest version.`

13. **Add search functionality** (included by default in mdbook)

14. **Test locally**
    ```bash
    mdbook serve docs
    # Open http://localhost:3000
    ```

15. **Validate all links**
    ```bash
    mdbook test docs
    ```

## Risks

### Technical Risks

1. **mdbook not available in CI**
   - **Mitigation**: Download prebuilt binary in workflow (shown in step 9)
   - **Fallback**: Use Docker image with mdbook pre-installed

2. **GitHub Pages deployment failures**
   - **Mitigation**: Use well-maintained `peaceiris/actions-gh-pages` action
   - **Fallback**: Manual deployment, or use Netlify/Vercel

3. **Broken links after migration**
   - **Mitigation**: Use `mdbook test` to validate links before deploying
   - **Mitigation**: Keep old docs with redirect notices during transition

4. **Search not working on deployed site**
   - **Mitigation**: Test deployed version before announcing
   - **Note**: Search is client-side JavaScript, should work out of the box

### Content Risks

5. **Information loss during migration**
   - **Mitigation**: Keep original docs intact with deprecation notices
   - **Mitigation**: Manual content review before deleting old files

6. **Documentation becoming outdated**
   - **Mitigation**: Add workflow that reminds to update docs on config changes
   - **Mitigation**: Keep docs close to code (in same repo)

### User Experience Risks

7. **Users linking to old docs**
   - **Mitigation**: Keep old docs with prominent redirect notices
   - **Mitigation**: Add redirects in README

8. **Complex navigation structure**
   - **Mitigation**: Keep SUMMARY.md flat (max 2 levels deep)
   - **Mitigation**: User testing with team members
