# Implementation Plan: Remove bao shim overlay

## 1. Problem Analysis

### What needs to be solved
The codebase currently includes a custom overlay for the `bao` package, which was a temporary workaround/shim needed before upstream changes were available. Now that [numtide/systemd-vaultd#65](https://github.com/numtide/systemd-vaultd/pull/65) has been merged, this overlay is no longer necessary and should be removed.

### Why it matters
- **Reduced maintenance burden**: Custom overlays require ongoing maintenance and testing
- **Upstream alignment**: Using upstream packages reduces divergence and improves compatibility
- **Cleaner codebase**: Removing temporary workarounds improves code clarity
- **Better updates**: Without the overlay, the package will automatically receive upstream updates

## 2. Technical Approach

### Strategy
Remove the bao overlay definition and all references to it from the Nix configuration, relying on the upstream nixpkgs version instead.

### Key decisions
- **Direct removal**: Since the upstream fix is merged, we can safely remove the overlay without replacement
- **Dependency verification**: Ensure no other parts of the codebase depend on overlay-specific behavior
- **Version compatibility**: Confirm the nixpkgs version used includes the merged PR changes

## 3. Implementation Steps

1. **Locate the bao overlay definition**
   - Search for `bao` overlay in `overlays/`, `flake.nix`, or overlay definition files
   - Identify the file(s) containing the shim overlay code

2. **Identify all references to the overlay**
   - Search for imports/references to the bao overlay
   - Check `flake.nix` for overlay applications
   - Grep for `bao` across Nix files to find usage sites

3. **Remove the overlay definition**
   - Delete the overlay file or remove the bao overlay section
   - Remove any associated derivation files

4. **Update overlay imports**
   - Remove bao overlay from the overlay list in `flake.nix` or similar
   - Update any `overlays = [ ... ];` lists that reference it

5. **Update package references**
   - Change any explicit `pkgs.bao` references that relied on the overlay to use the standard nixpkgs version
   - Verify no custom attributes from the overlay are used elsewhere

6. **Update flake lock**
   - Run `nix flake update` to ensure nixpkgs includes the upstream fix
   - Verify the nixpkgs input is recent enough to contain systemd-vaultd#65

7. **Clean up documentation**
   - Remove any README/doc mentions of the bao overlay workaround
   - Update any comments explaining why the overlay was needed

## 6. Risks

### Potential blockers
- **Nixpkgs version lag**: If the nixpkgs input is too old, it might not include the upstream fix
  - **Mitigation**: Update flake.lock to a recent nixpkgs revision
  - **Verification**: Check nixpkgs commit history for the bao update

- **Overlay-specific patches**: The overlay might have included additional patches beyond the upstream fix
  - **Mitigation**: Carefully review the overlay code before deletion
  - **Verification**: Test functionality thoroughly after removal

- **Transitive dependencies**: Other overlays might depend on the bao overlay
  - **Mitigation**: Search for references across all overlay files
  - **Verification**: Ensure `nix flake check` passes

### Unknowns
- Exact location of the overlay definition (needs code search)
- Whether the overlay includes functionality beyond systemd-vaultd#65
- Minimum nixpkgs version required for the upstream fix
- Whether any downstream consumers rely on this overlay

### Edge cases
- CI/CD systems might cache the old nixpkgs version
- Local developer environments might have pinned old versions
- The overlay might be conditionally applied based on system type
