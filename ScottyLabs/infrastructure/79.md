# Implementation Plan: AWS Account Provisioning for SES

## 1. Problem Analysis

### What Needs to be Solved
The credit-conserver system currently lacks email notification capabilities. Issue #79 requires setting up AWS Simple Email Service (SES) to enable the system to send notifications about:
- Workflow completion status (success/failure)
- Credit budget exhaustion warnings
- PR creation confirmations
- Error alerts when API limits are reached
- Daily/weekly summary reports

### Why This is Needed
Currently, the system runs as a GitHub Action with no proactive notifications. Users must manually check the Actions tab to see results. Email notifications via SES will provide:
- Immediate awareness of workflow failures
- Proactive alerts when credit budgets are running low
- Better monitoring of automated PR generation
- Audit trail of system activity

### Current State
- No email/notification infrastructure exists
- No AWS dependencies in `requirements.txt`
- No notification module in `modules/` directory
- Workflow runner returns summary dict but doesn't notify anyone
- GitHub Actions artifacts are the only output mechanism

## 2. Technical Approach

### Strategy
Use AWS SES in sandbox mode initially (no production verification needed), with a minimal notification module following the existing codebase patterns:

1. **Lazy integration**: Use `boto3` (AWS SDK) directly, no custom abstraction layers
2. **Configuration-driven**: Add SES settings to existing `config.yml` structure
3. **Optional feature**: System works without SES configured (graceful degradation)
4. **Environment-based secrets**: AWS credentials via GitHub Secrets (existing pattern)
5. **Single module**: One `modules/ses_notifier.py` file, called from workflow runner

### Key Decisions
- **boto3 only**: No helper libraries like `django-ses` or `flask-mail` (YAGNI)
- **Plaintext emails**: No HTML templates initially (complexity later if needed)
- **Configurable recipients**: Email addresses in config, not hardcoded
- **Error tolerance**: Email send failures logged as warnings, don't fail workflow
- **SES sandbox mode**: Start with verified sender/recipient, production mode optional

## 3. Implementation Steps

### Step 1: Add AWS Dependencies
1. Add `boto3>=1.34.0` to `requirements.txt`
2. Update GitHub Actions workflow to install new dependency

### Step 2: Extend Configuration Schema
1. Add `NotificationConfig` dataclass to `modules/config.py`:
   - `enabled: bool` (default False)
   - `sender_email: str`
   - `recipient_emails: list[str]`
   - `aws_region: str` (default "us-east-1")
2. Add `notifications` section to `config.yml.example`
3. Update `Config.from_env()` to load notification settings
4. Add AWS credentials to environment variable handling:
   - `AWS_ACCESS_KEY_ID` (from env)
   - `AWS_SECRET_ACCESS_KEY` (from env)

### Step 3: Create SES Notifier Module
Create `modules/ses_notifier.py` with:
1. `SESNotifier` class:
   - `__init__(config: NotificationConfig, aws_region: str)`
   - `send_workflow_summary(summary: dict) -> bool`
   - `send_error_alert(message: str, repo: str) -> bool`
   - `send_credit_warning(usage: float, limit: float) -> bool`
2. Use `boto3.client('ses')` directly
3. Catch `botocore.exceptions.ClientError` and log warnings (don't crash)
4. Return `True` on success, `False` on failure
5. Add `# ponytail: plaintext only, add HTML templates if users request` comment

### Step 4: Integrate with Workflow Runner
Modify `modules/parallel_workflow_runner.py`:
1. Import `SESNotifier` conditionally
2. Initialize notifier in `__init__` if `config.notifications.enabled`
3. Call `notifier.send_workflow_summary(summary)` at end of `run()`
4. Call `notifier.send_error_alert()` in exception handlers

## 6. Risks

### Blockers
1. **AWS account limits**: New AWS accounts start in SES sandbox mode
   - Only verified email addresses can send/receive
   - 200 emails per day limit
   - **Mitigation**: Document sandbox limitations, provide production mode upgrade steps

2. **AWS credential security**: Secrets exposed in logs
   - **Mitigation**: Never log AWS credentials, use GitHub Secrets, add to .gitignore

3. **Email deliverability**: Emails marked as spam
   - **Mitigation**: Use proper FROM address, add SPF/DKIM records (documentation only)

### Unknowns
1. **User email address**: No way to auto-detect recipient from GitHub
   - **Resolution**: Make `recipient_emails` required in config when enabled

2. **Cost**: SES pricing unknown to user
   - **Resolution**: Document SES free tier (62,000 emails/month)

3. **Regional restrictions**: SES not available in all AWS regions
   - **Resolution**: Default to `us-east-1`, document supported regions

### Edge Cases
1. **No internet during workflow**: boto3 client creation may hang
   - **Mitigation**: Wrap boto3 initialization in try/except with 5s timeout

2. **SES quota exceeded**: 200/day sandbox limit hit
   - **Mitigation**: Catch `MessageRejected` exception, log warning

3. **Invalid email format**: Typo in config.yml recipient
   - **Mitigation**: Validate email format in `Config.validate()` using regex
